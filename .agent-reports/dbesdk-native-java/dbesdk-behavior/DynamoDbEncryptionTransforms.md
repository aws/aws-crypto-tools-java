# Behavior Spec: DynamoDbEncryptionTransforms

Source of truth: `~/github/dbesdk/aws-database-encryption-sdk-dynamodb/DynamoDbEncryption/dafny/DynamoDbEncryptionTransforms/` (primary checkout). Generated by the dafny-behavior-discovery procedure; see `DynamoDbEncryptionTransforms-discovery.md` for the checklist + evidence.

## 0. What this module is

The DDB-SDK integration layer: a client that wraps DynamoDB request/response objects (the "interceptor" hooks a DDB call passes through), applying client-side encryption and searchable-encryption (beacons) per table. It is **thin middleware** — it orchestrates two things it does not itself implement:
1. the per-table **item encryptor** (`DynamoDbItemEncryptor`, already native) — does the actual encrypt/decrypt;
2. the **beacon-support layer** `DynamoDBSupport` (aka `BS`), which lives in the *DynamoDbEncryption* module (`DynamoDbEncryption/src/DDBSupport.dfy`), not here — does all beacon math and expression rewriting.

**Scope flag for the native port:** "the full transforms module" = this middleware (28 operations) **plus** the `DynamoDBSupport` beacon layer it calls. The middleware is small and mechanical; `DynamoDBSupport` (write/remove beacons, Query/Scan FilterExpression rewriting via `FilterExpr`, virtual fields, compound beacons) is the large searchable-encryption substance and is only partially covered by the beacon work done so far (`BeaconVersion.generateEncryptedBeacons` ≈ part of `GetEncryptedBeacons`). Treat `DynamoDBSupport` as its own discovery/build sub-effort.

## 1. Public surface

**Construction:** `DynamoDbEncryptionTransforms(config: DynamoDbTablesEncryptionConfig) -> Result<Client, Error>`, where the config is `map<physicalTableName, DynamoDbTableEncryptionConfig>`.

**Operations (28):** for each of PutItem, GetItem, UpdateItem, DeleteItem, BatchWriteItem, BatchGetItem, TransactWriteItems, TransactGetItems, Query, Scan, ExecuteStatement, BatchExecuteStatement, ExecuteTransaction — an `Input` (before the DDB call) and `Output` (after) transform; plus `ResolveAttributes` and `GetNumberOfQueries`. Each takes `{sdkInput}` (Input) or `{originalInput, sdkOutput}` (Output) and returns `{transformedInput}` / `{transformedOutput}`.

## 2. Client construction (Index.dfy)

Per table entry, in sorted-key order:
- Convert the search config (`SearchConfigToInfo.Convert`) → optional native `SearchInfo` (the beacon/keystore layer).
- **Signed beacons**: `search.curr().ListSignedBeacons()`. Init MUST fail if a signed-beacon `NAME` is already present in `attributeActionsOnEncrypt`, in `allowedUnsignedAttributes`, or begins with `allowedUnsignedAttributePrefix` (predicate `IsConfigured`). Each signed beacon name is then auto-added to `attributeActionsOnEncrypt` as `SIGN_ONLY`. Beacon names must be valid DDB attribute names.
- Build a per-table `DynamoDbItemEncryptor` from the beacon-augmented actions + {logical/partition/sort names, allowedUnsigned*, algorithmSuiteId, keyring|cmm, legacyOverride, plaintextOverride}.
- Internal `TableConfig` = {physicalTableName, logicalTableName, partitionKeyName, sortKeyName, itemEncryptor, search, plaintextOverride (defaulting to `FORBID_PLAINTEXT_WRITE_FORBID_PLAINTEXT_READ`)}.
- Init MUST fail on a duplicate `logicalTableName` mapped from two physical tables (one-to-one logical↔physical).

## 3. Per-operation contracts (plain language)

Universal rule: if `TableName !in config.tableEncryptionConfigs`, the request/response is returned **unchanged**. Read-outputs also passthrough when the item list/map is absent.

### Item writes
- **PutItemInput**: passthrough if `IsPlainWrite` (table unconfigured OR plaintextOverride == `FORCE_PLAINTEXT_WRITE_ALLOW_PLAINTEXT_READ`). Else: reject legacy `Expected`(must be empty)/`ConditionalOperator`(must be unset); `IsWriteable(item)` (no attr name starts with `aws_dbe_`); `TestConditionExpression`; `partition = GetRandomPartition(item)`; `item' = AddSignedBeacons(item, partition)`; `encrypted = itemEncryptor.EncryptItem(item')`; `keyId = GetKeyIdFromHeader(encrypted)`; `beacons = GetEncryptedBeacons(originalItem, keyId, partition)`; result `Item = encrypted.encryptedItem + beacons`.
- **PutItemOutput**: passthrough if unconfigured OR no `Attributes`; else `DecryptItem(Attributes)` → `RemoveBeacons` → replace `Attributes`. (Attributes present only when `ReturnValues=ALL_OLD` replaced an item.)
- **DeleteItemInput**: reject legacy `Expected`/`ConditionalOperator`; `TestConditionExpression`; else unchanged.
- **DeleteItemOutput**: same shape as PutItemOutput (ALL_OLD Attributes → decrypt + removebeacons).
- **UpdateItemInput**: reject legacy `Expected`/`AttributeUpdates`/`ConditionalOperator`; `TestUpdateExpression`; else unchanged.
- **UpdateItemOutput**: if `ReturnValues` is `ALL_OLD`/`ALL_NEW` and Attributes present → decrypt + removebeacons. If `UPDATED_OLD`/`UPDATED_NEW` (partial item) → **MUST fail** if any returned attribute `IsSigned` (can't verify a partial item); otherwise passthrough. Unconfigured/no-Attributes → passthrough.

### Item reads
- **GetItemInput**: always passthrough (no transform). **GetItemOutput**: unconfigured OR no `Item` → passthrough; else `DecryptItem(Item)` → `RemoveBeacons` → replace `Item`.

### Batch
- **BatchWriteItemInput**: per table, per `WriteRequest`: a `PutRequest` on an encrypted (non-plain-write) table → same encrypt+beacon write path as PutItem (`Item = encryptedItem + beaconAttrs`); a `DeleteRequest` / absent `PutRequest` / plain-write table → unchanged.
- **BatchWriteItemOutput**: `UnprocessedItems` absent → passthrough. Else each unprocessed `PutRequest` item is replaced by its **original plaintext** request item, matched by partition+sort key (`GetOrigItem`); a table in UnprocessedItems but not in the original request → error; non-encrypted tables unchanged.
- **BatchGetItemInput**: passthrough. **BatchGetItemOutput**: per table in `Responses`, if configured → decrypt + removebeacons each item (any decrypt failure fails the whole op); unconfigured table unchanged.

### Transact
- **TransactWriteItemsInput**: MUST fail if any `TransactItem` has none of Put/Update/Delete/ConditionCheck set (guards against a future 5th field). For each: validate `ConditionCheck`/`Delete` ConditionExpression; validate `Update` Update+Condition expressions; a `Put` on an encrypted table → encrypt+beacon write path; everything else unchanged.
- **TransactWriteItemsOutput**: passthrough (no data).
- **TransactGetItemsInput**: passthrough. **TransactGetItemsOutput**: `Responses` absent → passthrough; response count MUST equal request `TransactItems` count; per item, by its `Get.TableName`: unconfigured or absent item → unchanged; else decrypt + removebeacons.

### Query / Scan (the beacon read-rewrite path)
- **QueryInput**: unconfigured → passthrough. Else reject legacy `AttributesToGet`/`KeyConditions`/`QueryFilter`/`ConditionalOperator`; `QueryInputForBeacons` rewrites KeyCondition/Filter expression references to beaconed attributes into their beacon attributes.
- **QueryOutput**: unconfigured OR no `Items` → passthrough. Else: resolve the beacon `keyId` from the key/filter expression (`GetBeaconKeyId`); per item `DecryptItem`; **multi-tenant filter** — if a keyId resolved and the decrypted item's parsed header is present, keep the item only if it has exactly one EDK whose `keyProviderInfo` equals the queried keyId (mismatched-tenant items are silently dropped, not errored); then `QueryOutputForBeacons` filters the decrypted result.
- **Scan**: same as Query but Input rejects `AttributesToGet`/`ScanFilter`/`ConditionalOperator`, uses `ScanInputForBeacons`; Output resolves keyId from the filter expression only (no KeyConditionExpression) and uses `ScanOutputForBeacons`.

### PartiQL (statement-based) — unsupported on encrypted tables
- **ExecuteStatementInput**: parse the table name from the statement (`DdbStatement.TableFromStatement`); if that table is configured (encrypted) → **hard error** "ExecuteStatement not Supported on encrypted tables" and no network call; else passthrough. Output passthrough.
- **BatchExecuteStatementInput** / **ExecuteTransactionInput**: same, checking every statement; any statement whose table is encrypted → hard error. Outputs passthrough.
- `DdbStatement.TableFromStatement` parses SELECT/UPDATE/DELETE/INSERT/EXISTS PartiQL grammar (whitespace strip, token scan, quote handling, `Table.Index` → `Table`), returning the table name or a parse failure.

### ResolveAttributes / GetNumberOfQueries
- **ResolveAttributes**: unconfigured or no search → empty `{VirtualFields:{}, CompoundBeacons:{}}`; else `GetRandomPartition` + `GetVirtualFields` + `GetCompoundBeacons` (both reject a beacon version != 1).
- **GetNumberOfQueries**: unconfigured or no search → `1`; else `DynamoDBSupport.GetNumberOfQueries(search.versions[0], query)`.

## 4. The DynamoDBSupport seam (dependency in the DynamoDbEncryption module)

The middleware calls these; they are NOT in this module (`DDBSupport.dfy` under DynamoDbEncryption). Each must exist natively for the corresponding transform to work:
- `IsWriteable(item)` — reject any attr name beginning with `aws_dbe_`.
- `AddSignedBeacons(search, item, partition)` — add signed-beacon attributes to the plaintext item **before** encryption.
- `GetEncryptedBeacons(search, originalItem, keyId, partition)` — compute the `aws_dbe_b_*` encrypted-beacon attributes from the **original plaintext** item (appended **after** encryption). (Partially native: `BeaconVersion.generateEncryptedBeacons`.)
- `RemoveBeacons(search, item)` — strip beacon attributes from a decrypted item before returning.
- `GetBeaconKeyId(search, keyExpr, filterExpr, values, names)` — resolve the beacon key id referenced by a query/scan.
- `QueryInputForBeacons` / `QueryOutputForBeacons` / `ScanInputForBeacons` / `ScanOutputForBeacons` — rewrite query/scan expressions to beacons (input) and filter decrypted results (output); depends on the `FilterExpr` expression parser/rewriter.
- `GetVirtualFields` / `GetCompoundBeacons` — compute virtual fields and compound beacons (ResolveAttributes).
- `IsSigned`, `TestConditionExpression`, `TestUpdateExpression` — schema validation over `attributeActionsOnEncrypt`.
- `GetNumberOfQueries` — beacon sub-query fan-out count.
- `GetKeyIdFromHeader(config, encryptOutput)` (this IS in the transforms middleware): MultiLoc keySource → require exactly 1 EDK with keyProviderId `aws-kms-hierarchy`, return decoded keyProviderInfo; SingleLoc → None.

## 5. Error behavior

- Module error: `DynamoDbEncryptionTransformsException(message)`. Item-encryptor errors are wrapped as `AwsCryptographyDbEncryptionSdkDynamoDbItemEncryptor(...)`; DDBSupport errors as `AwsCryptographyDbEncryptionSdkDynamoDb(...)`.
- Legacy DDB parameters are hard errors on encrypted tables (per op; see §3).
- PartiQL on an encrypted table is a hard error with no network call.
- UpdateItem UPDATED_OLD/UPDATED_NEW returning a signed attribute is a hard error.
- Test vector confirms error wrapping shape: an over-long attribute name surfaces as `...ItemEncryptor` → `...DynamoDb` → `DynamoDbEncryptionException("Attribute name must be between 1 and 65535 UTF-8 bytes")` (nested enum wrapping).

## 7. Non-obvious details (highest-value)

1. **Signed vs encrypted beacons differ in placement**: signed beacons are added to the plaintext item *before* `EncryptItem` (and auto-configured SIGN_ONLY at construction); encrypted `aws_dbe_b_*` beacons are computed from the *original* plaintext and appended *after* encryption. The write path reads the item twice (original for encrypted beacons, signed-augmented for encryption).
2. **Query/Scan multi-tenant filtering silently drops** items whose header EDK keyProviderInfo ≠ the queried beacon keyId — not an error.
3. **BatchWriteItem output** restores *original plaintext* for unprocessed puts by PK+SK match, not by decryption.
4. **UpdateItem UPDATED_* + signed attribute = hard error** (partial item is unverifiable).
5. **GetItem/BatchGetItem/Transact\* input transforms are pure passthrough**; all their work is in the output transform.
6. **PartiQL is categorically unsupported** on encrypted tables (error, no network call) — not merely unencrypted.
7. **`IsPlainWrite` vs plaintext read**: only `FORCE_PLAINTEXT_WRITE_ALLOW_PLAINTEXT_READ` bypasses the write path; the read-side plaintext behavior is handled inside the item encryptor's DecryptItem, not here.
8. The Dafny `History` fields (`itemEncryptor.History.DecryptItem`) in the `ensures` clauses are verification scaffolding — they document that exactly one DecryptItem happens, not a runtime-queryable requirement.

## 8. Explicit non-goals

- No support for legacy DDB parameters (`Expected`, `ConditionalOperator`, `AttributesToGet`, `KeyConditions`, `QueryFilter`, `ScanFilter`, `AttributeUpdates`) on encrypted tables.
- No PartiQL on encrypted tables.
- `GetNumberOfQueries` returns 1 when there is no search config (not an error).
- Beacon version must be 1 (`GetVirtualFields`/`GetCompoundBeacons` reject otherwise).
