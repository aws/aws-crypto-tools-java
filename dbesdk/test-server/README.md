# DB-ESDK TestServer — native Java Language_Server

This directory hosts the **native (non-Dafny) Java DB-ESDK Language_Server** for
the cross-language DB-ESDK TestServer. The shared model, Tests suite, and
orchestrator live in
[`aws-crypto-tools-commons`](https://github.com/aws/aws-crypto-tools-commons)
under `dbesdk/test-server/`; this repo carries only the server and its
per-server config.

## Layout

- `server/` — the Java Language_Server. Its rpcv2Cbor request decoding,
  response/error encoding, and routing are generated by the smithy-java
  `java-codegen` plugin (SERVER mode) from the single source-of-truth Smithy
  model in commons; only the operation handler bodies are hand-written. The
  server carries **no** copy of the model — it is supplied at build time via the
  required `-PmodelDir` Gradle property. This directory also holds the
  per-server config trio below, co-located with the server as the commons
  `java-native` entry's `configPath` (`dbesdk/test-server/server`) expects.
- `server/server-config.json` / `server/feature-config.json` /
  `server/bug-config.json` — the per-server config trio the orchestrator reads.
  `feature-config.json` is the Feature_Declaration: its `supportedFeatures` +
  `unsupportedFeatures` must together equal the commons Feature_Catalog, and the
  orchestrator skips any test that needs a feature not declared supported. Move
  a feature from `unsupportedFeatures` to `supportedFeatures` as its
  implementation lands and the orchestrated run starts exercising that feature's
  tests automatically.

## How it is run

The server is registered in the commons orchestrator as the `java-native`
entry in `config/server-config.json`; the orchestrator launches it with the
same smithy-java `runServer` shape as the Dafny `java` server.

- **Cross-language run** (from a commons checkout): `make orchestrate`. To run
  against this repo's local working tree — e.g. an unmerged branch — instead of
  the ref pinned in `config/server-config.json`, the commons Makefile applies a
  working-tree overlay: `make orchestrate DBESDK_JAVA_NATIVE_REPO=<abs path to
  this repo>` (auto-detected when this repo is a sibling of the commons
  checkout). In CI, the commons `DB-ESDK TestServer` workflow takes a
  `java_native_ref` input that checks out this repo at a ref and overlays it the
  same way.
- **Fast per-PR gate** (this repo): `.github/workflows/dbesdk-native-test-server.yml`
  builds `server/` and runs its unit tests on every change, checking out commons
  only to supply the model. No AWS credentials, no orchestrator.
- **Standalone** (manual over-HTTP round trip): from `server/`,
  `./gradlew runServer -PmodelDir=<commons>/dbesdk/test-server/model` (JDK 21+).

## Delegation target

Handlers delegate through the `registry` seam (`DbesdkClient` /
`TransformsClient` / `StructuredClient`, implemented by the `Real*Client`
classes). That seam currently calls the published AWS Database Encryption SDK
for DynamoDB (Java) to prove the harness end to end; it is the single point that
a native Java DB-ESDK implementation replaces as that implementation lands.
